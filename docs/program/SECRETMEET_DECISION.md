# SecretMeet keep vs sunset (E-803)

## Options

| Option | Pros | Cons |
|--------|------|------|
| **Keep + moderate** | Differentiator; growth channel | Abuse, safety, support cost |
| **Sunset** | Focus capacity on classroom/enterprise | Lose casual users |

## Proposed decision (draft)

**Keep** SecretMeet behind clearer ToS + rate limits through Y2Q2; revisit sunset if moderation load > 1 eng-week/quarter or App Store risk.

## Near-term controls

- Queue rate limit already on secret routes  
- No anonymous persistent identity beyond `qm_userId`  
- Add report/block before marketing SecretMeet heavily
